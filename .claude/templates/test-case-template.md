# Test Case Template

Use this template to write structured test cases for QA. Generated by `/gen-tests` and reviewed by the `qa-reviewer` agent. Store test case documents in `docs/qa/test-cases-{{feature}}.md`.

---

## How to Use

1. Run `/gen-tests` to auto-generate a test matrix from the feature spec
2. Copy this template and fill in each scenario
3. Prioritise: P0 must be covered before any release; P1 before QA sign-off; P2 where time allows
4. During execution, fill in Actual Result and Status columns

---

## Test Case Fields

| Field | Description |
|---|---|
| **TC-ID** | Unique ID: `TC-{{FEATURE}}-{{number}}` e.g. `TC-AUTH-001` |
| **Feature** | Feature or module being tested |
| **Scenario** | One-line description of what is being tested |
| **Type** | Positive / Negative / Edge / Regression / Security |
| **Priority** | P0 (blocking) / P1 (high) / P2 (medium) |
| **Preconditions** | System state required before test can run |
| **Test Steps** | Numbered, specific actions to perform |
| **Expected Result** | Exact observable outcome if the system behaves correctly |
| **Actual Result** | Filled during execution |
| **Status** | PASS / FAIL / BLOCKED / NOT RUN |
| **Defect Ref** | Jira ticket if status is FAIL or BLOCKED |

## Required Coverage per Feature

Every feature must have test cases covering:

| Scenario Type | Minimum Cases | Priority |
|---|---|---|
| Happy path (primary user flow) | 1 per user story | P0 |
| Auth failure (unauthenticated request) | 1 per protected endpoint | P0 |
| Authorization failure (wrong role/permission) | 1 per permission gate | P0 |
| Tenant isolation (cross-tenant data access attempt) | 1 per data endpoint | P0 |
| Invalid input (missing required field) | 1 per required field | P0 |
| Invalid input (wrong type/format) | 1 per validated field | P1 |
| Boundary values (min/max) | 1 per numeric or length constraint | P1 |
| State transition (invalid transition attempt) | 1 per state machine | P1 |
| Soft delete (deleted item not in list) | 1 per deletable entity | P1 |
| Pagination (boundary pages, empty results) | 1 per list endpoint | P2 |
| Concurrent write safety | 1 per write-heavy endpoint | P2 |
