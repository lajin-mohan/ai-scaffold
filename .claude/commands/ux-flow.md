# /ux-flow

Legacy alias. Flow work now belongs inside `/ux-analysis`.

Use:

```text
/ux-analysis {module-or-task-id}
```

`/ux-analysis` must include happy paths, error paths, empty-state paths, permission paths, multi-role paths, and screen/task candidates.

Do not create a standalone `02-flows.md` as a required pipeline stage for new UX work. If old docs need migration, archive them as legacy source material and link them from the relevant task.
