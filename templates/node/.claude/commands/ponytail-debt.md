# /ponytail-debt

Harvests every `ponytail:` comment in the repository into a single tracke.ai-scaffold/tasks/er at `tasks/ponytail-debt.md`. Surfaces shortcut markers that lack a named upgrade path (`no-trigger`) so they don't rot silently.

Invokable by:
- The user, manually.
- The `architect` reviewer inside the Stage 6 `/review` parallel review when over-engineering findings cite `ponytail:` markers — not on every review.
- The `architect` agent during Stage 3 `/architecture-review` when shortcuts are suspected in the design.

**Read-only by default.** Reports, doesn't write. Pass `--write` to update the ledger file.

---

## Usage

```
/ponytail-debt                          # read-only: print ledger to stdout
/ponytail-debt --write              .ai-scaffold/tasks/update tasks/ponytail-debt.md
/ponytail-debt --path apps/api          # scope the harvest to a subtree
/ponytail-debt --missing-trigger        # show only ponytail: comments with no upgrade path
```

---

## Why this command exists

A `ponytail:` comment that names a ceiling and a trigger to revisit is a *deliberate shortcut* — the author is saying "I know this is wrong, here's the tripwire." The trap is shortcuts without a trigger. They rot. "Later" becomes "never" because no one remembers to come back.

This command does the bookkeeping so the shortcuts don't disappear into the codebase.

---

## The marker convention

A valid `ponytail:` comment has three fields:

```
// ponytail: <what was simplified>. ceiling: <the limit>. upgrade: <the trigger>.
```

| Field | Required | Meaning |
|---|---|---|
| `ponytail:` label | Yes | Marks the comment as a deliberate shortcut (not a TODO, not a FIXME) |
| `what was simplified` | Yes | One line describing the shortcut |
| `ceiling:` | Yes | The known limit — what breaks or degrades past this point |
| `upgrade:` | Yes | The trigger that says "revisit this" — usually a metric, a count, or a date |

Examples:

```typescript
// ponytail: O(n²) scan over candidate list. ceiling: ~10k candidates before latency > 500ms.
// upgrade: switch to indexed lookup when production list size exceeds 1k.
for (const candidate of candidates) {
  if (matches(candidate, query)) results.push(candidate)
}

// ponytail: in-process debounce, no Redis. ceiling: per-instance only, no cross-replica dedup.
// upgrade: when running > 1 replica, move to a shared store.
const debounced = debounce(handler, 250)
```

A comment that says `// ponytail: this exists.` with no `ceiling` or `upgrade` is **`no-trigger`** and is flagged by this command.

## Process

### Step 1 — Find every `ponytail:` comment

The harvester must **only** match real source-code comments. The convention is documented in several places — `.claude/rules/ponytail-ladder.md`, `.claude/rules/coding-standards.md` "Shortcut Markers", `.ai-scaffold/HOW-TO-USE.md` "Ponytail Integration", the two `ponytail-*.md` commands thems.ai-scaffold/tasks/ and the ledger at `tasks/ponytail-debt.md` — and the convention is also reproduced as code-fenced examples in those files. None of these documentation occurrences are debt; they are the definition of the.ai-scaffold/_ai/vention.

#### Exclusions

| Excluded path | Reason |
|---|---|
| `node_modules/`, `dist/`, `build/`, `.next/`, `_ai/`, `.claude/work/` | Build output, vendored deps, AI scratch |
| `*.lock`, `*.lockb`, `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `composer.lock` | Lockfile.ai-scaffold/tasks/ editable code |
| `tasks/ponytail-debt.md` | The ledger itself — its body is regenerated by this command |
| `.claude/commands/ponytail-*.md` | The two commands themselves — they document the convention |
| `.claude/rules/ponytail-ladder.md` | The ladder rule — it documents the convention |
| `.claude/rules/coding-standards.md` | Contains the `Shortcut Markers` section that defines the convention |
| `.ai-scaffold/HOW-TO-USE.md` | Contains the `Ponytail Integration` se.ai-scaffold/tasks/that documents the commands |
| `tasks/lessons.md` | References the conventi.ai-scaffold/docs/ a lesson, .ai-scaffold/docs/ debt mar.ai-scaffold/docs/
| `docs.ai-scaffold/docs/p/*`, `docs/brd/*`, `docs/ux/*`, `docs/architecture/*` | Project narrative documents — not sour.ai-scaffold/CONTRI.ai-scaffold/CHANGELOG.mdE.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, `CLAUDE.md` | Top-level project docs |
| Any line inside a fenced code block in any `.md` file | Code fences are examples, not live markers |

#### Grep (source-code files only)

The harvester greps files whose extension is in a source-code allowlist, not by exclusion. The allowlist is the inverse: only the languages this scaffold produces code in.

```bash
# Source-code files only — markdown and docs are excluded entirely.
# .sql and .sh are included: the regex supports # and -- comments, and
# migrations and scripts are exactly where shortcut markers most often live.
# .yml/.yaml are excluded: YAML is config, not source code, so shortcut
# debt markers are not harvested there. A 'ponytail:' token in YAML would
# be a config value, not a comment on a code unit.
grep -rnE '(//|#|/\*|--) ?ponytail: \S+' \
  --include='*.ts' --include='*.tsx' --include='*.js' --include='*.jsx' \
  --include='*.py' --include='*.go' --include='*.rs' --include='*.java' \
  --include='*.kt' --include='*.swift' --include='*.php' --include='*.rb' \
  --include='*.c' --include='*.cpp' --include='*.h' --include='*.hpp' \
  --include='*.cs' --include='*.scala' --include='*.cfm' --include='*.cfc' \
  --include='*.sql' --include='*.sh' \
  --exclude-dir=node_modules --exclude-dir=dist --exclude-dir=build \
  --exclude-dir=.next --exclude-dir=_ai --exclude-dir=.claude/work
```

#### Multi-line block comments

For block comments where `ponytail:` appears on a continuation line (less common, but supported), use a second pass with a multiline-aware tool:

```bash
# Optional second pass for block-comment continuations
grep -rnE 'ponytail:' \
  --include='*.ts' --include='*.tsx' --include='*.js' --include='*.jsx' \
  --include='*.py' --include='*.go' --include='*.rs' --include='*.java' \
  --include='*.kt' --include='*.swift' --include='*.php' --include='*.rb' \
  --include='*.c' --include='*.cpp' --include='*.h' --include='*.hpp' \
  --include='*.cs' --include='*.scala' --include='*.cfm' --include='*.cfc' \
  --include='*.sql' --include='*.sh' \
  --exclude-dir=node_modules --exclude-dir=dist --exclude-dir=build \
  --exclude-dir=.next --exclude-dir=_ai --exclude-dir=.claude/work
```

A match from the second pass is only counted if the first pass didn't already pick it up (dedup by `file:line`).

#### Per-match parse

For each match, parse:

- **file** and **line** from the grep output
- **language** from the file extension (used to render the marker in the ledger)
- **fields** — extract `ponytail:`, `ceiling:`, `upgrade:` from the comment text. Field parsing is line-scoped: each field is expected on the same line as `ponytail:` or on a continuation line. If a field is missing, the marker is `no-trigger` or `malformed` per Step 2.

### Step 2 — Classify each marker

| Status | Detection |
|---|---|
| `valid` | Has all three fields: `ponytail:`, `ceiling:`, `upgrade:` |
| `no-trigger` | Has `ponytail:` and `ceiling:` but no `upgrade:` — or the `upgrade:` value is vague ("when needed", "later", "TBD") |
| `malformed` | Has `ponytail:` but is missing `ceiling:` or is otherwise unparseable |

### Step 3 — Group and present

Group by file, sort by line number. Show counts at the end.

```
## Ponytail Debt Ledger — <branch> @ <sha>
Scanned: <N> files
Markers found: <total>
  valid:        <count>
  no-trigger:   <count>   ← rot risk
  malformed:    <count>   ← fix at source

─── By file ───

- L34 (typescript): O(n²) scan over candidate list. ceiling: ~10k candidates before latency > 500ms. upgrade: switch to indexed lookup when production list size exceeds 1k.  [valid]
- L67 (typescript): hand-rolled relevance ranking. ceiling: no ML, no personalization. upgrade: when ranking quality is a top-3 support driver, integrate a vetted ranking library.  [valid]

### apps/web/src/components/Toast.tsx
- L12 (typescript): in-memory queue, max 3 visible. ceiling: > 3 toasts are dropped. upgrade: if product surfaces a "show all" view, switch to a queue lib.  [valid]

### apps/api/src/utils/date.ts
- L8 (typescript): naive date parsing. ceiling: ambiguous formats silently misparse. upgrade: when we add locales.  [no-trigger]
  ↑ vague upgrade ("when we add locales" — when? what's the trigger metric?)

─── Action items ───
1. Fix <count> `no-trigger` markers — every shortcut needs a concrete trigger
2. Fix <count> `malformed` markers — the convention is a three-field contract
3. Review <count> `valid` marker.ai-scaffold/tasks/r than 6 months for relevance
```

### Step 4 — Write (only with `--write`)

When `--write` is passed, update `tasks/ponytail-debt.md`:

- Replace the body of the existing ledger file with the new scan results
- Preserve the file's preamble (attribution, format spec)
- Append a footer with the scan.ai-scaffold/tasks/tamp and total count
- Do not create the file if it doesn't e.ai-scaffold/tasks/nless `--init`.ai-scaffold/tasks/so passed

Th.ai-scaffold/tasks/ult `tasks/ponytail-debt.md` is a tracked, per-project artifact — like `tasks/lessons.md`, `tasks/todo/`, and `tasks/done/`.

### Step 5 — Stop

The command ends. It does not modify source code, does not open tickets, does not fix `no-trigger` marke.ai-scaffold/tasks/ reports; humans triage.

---

## What this command does NOT do

- Does not write source code. It only writes `tasks/ponytail-debt.md` (with `--write`).
- Does not fix `no-trigger` markers. Those need a human decision on the actual trigger.
- Does not validate the *correctness* of `ceiling` or `upgrade` values. The author decides what's vague.
- Does not page anyone. No alerts, no notifications. The ledger is consulted at review time.

## Rules

- A valid `ponytail:` comment has three fields: `ponytail:`, `ceiling:`, `upgrade:`. Anything less is a flagged status.
- The `upgrade:` field must name a concrete trigger — a metric, a count, a date, or a clear condition. Vague values ("later", "when needed", "TBD") .ai-scaffold/tasks/eated as `no-trigger`.
- Read-only by default. Writes only happen with explicit `--write`.
- One ledger file: `tasks/ponytail-debt.md`. Don't fork into per-module ledgers.
- The ledger is tracked in git. It's an audit trail, not scratch space.
