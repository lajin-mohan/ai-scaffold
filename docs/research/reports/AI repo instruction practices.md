# Shrink the core, enforce the rest

The current evidence points to one answer from vendors, top repos and studies alike. **Keep a short always-loaded file of facts the agent cannot work out for itself: commands, gotchas, decisions and boundaries.** Move procedures into on-demand skills and area rules into path-scoped files. Put every rule that must hold without exception into hooks, deny rules or CI rather than prose. Anthropic's documented target is **"under 200 lines per CLAUDE.md file"**. Its docs also say **an unscoped `.claude/rules` file is "mechanically identical" to putting that content in CLAUDE.md**. By that measure, AI Scaffold's 16 unscoped rule files plus its ~475-line template CLAUDE.md (~37K estimated tokens) work as one always-loaded file about seven times the size of the median root file in 23 prominent public repos (173 lines, ~12.6 KB). The measured evidence is more modest than the vendor advice. The best controlled study found that **context files are followed but do not significantly raise task success, and they raise inference cost by roughly 20%**. A factorial study found that **even a trivial prompted rule was followed only 45–84% of the time, and compliance falls as a session goes on**. So the case for a lean core rests on cost, attention, maintainability and documented loading mechanics, not on a proven success gain. The case for moving non-negotiables into hooks and CI rests on prompt rules being measurably probabilistic. Wave B's direction is well supported. Two specifics need adjusting: the ~10K-token target is loose next to both observed practice and Codex's 32 KiB AGENTS.md cap, and the proposed rule headers need to map onto `paths:` frontmatter to have any mechanical effect.

## Vendors converge on a small always-on layer and on-demand everything else

Anthropic's current Claude Code docs are the most specific. They say to **"target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence"** ([Memory](https://code.claude.com/docs/en/memory)) **[Doc]**. On what to keep, they say to "only write down what Claude can't find by reading the repo", and give a two-question test: "Could it find this by reading the code? Would it actually go and look? If both are yes, leave it out" ([Best practices](https://code.claude.com/docs/en/best-practices)) **[Doc]**. The content they recommend keeping is exact test, typecheck and lint commands (including how to run one test file), "places where the code is misleading", "decisions that aren't in the repo", and "anything you've had to correct twice already". The docs' own example file has three sections (`# Commands`, `# Conventions`, `# Gotchas`) and about eight lines ([Best practices](https://code.claude.com/docs/en/best-practices)) **[Doc]**. Multi-step procedures, or entries that matter for only one part of the codebase, "move it to a skill or a path-scoped rule instead" ([Memory](https://code.claude.com/docs/en/memory)) **[Doc]**. The docs are not fully consistent on one point. The best-practices page lists "describe your architecture and file layout" under "what you can stop doing". The memory and features pages still list project layout and architecture as CLAUDE.md content ([Features overview](https://code.claude.com/docs/en/features-overview)) **[Doc]**.

The loading mechanics matter more than the advice, because they decide what a scaffold actually costs. **"Rules without `paths` frontmatter are loaded at launch with the same priority as `.claude/CLAUDE.md`"** ([Memory](https://code.claude.com/docs/en/memory)). Anthropic's June 2026 post says it plainly: **"An unscoped rule is mechanically identical to putting the content in CLAUDE.md"** ([Steering Claude Code, Jun 18 2026](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)) **[Doc]**. `@path` imports "don't reduce its context cost, because imported files load together with the CLAUDE.md that imports them" **[Doc]**. `paths` is "the only field Claude Code reads from a rule; any other field is ignored", and malformed YAML makes the rule load as if unscoped ([Memory](https://code.claude.com/docs/en/memory)) **[Doc]**. CLAUDE.md "is delivered as a user message after the system prompt", with "no guarantee of strict compliance" ([Memory](https://code.claude.com/docs/en/memory)) **[Doc]**. Subagents "load the full CLAUDE.md hierarchy, including project rules" (Explore and Plan skip it) ([Sub-agents](https://code.claude.com/docs/en/sub-agents)) **[Doc]**. Skills load only name and description up front. Custom commands "have been merged into skills". The skill listing budget "scales at 1% of the model's context window", and the least-invoked descriptions are dropped first on overflow. `disable-model-invocation: true` removes a skill's description from context entirely. Anthropic says to keep SKILL.md under 500 lines because a loaded skill "stays in context across turns" ([Skills](https://code.claude.com/docs/en/skills)) **[Doc]**.

On style, Anthropic now classes emphasis as legacy. **"Current ones follow a plainly worded line, and piling on emphasis mostly makes Claude over-apply the rule. If it's a rule that can't bend, turn it into a hook or a deny rule. If the line is getting lost in a long file, the file needs to be shorter"** ([Best practices](https://code.claude.com/docs/en/best-practices)) **[Doc]**. Its platform prompting page says Opus 4.5/4.6 prompts written to avoid under-triggering "might now overtrigger", and recommends softening "CRITICAL: You MUST" language ([Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-4-best-practices)) **[Doc]**. The skill-authoring guide is not fully aligned: it still shows "MUST filter" and "ALWAYS use this exact template structure" for strict formats ([Skill best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)) **[Doc]**. OpenAI says something similar for GPT-5. **"Contradictory or vague instructions can be more damaging to GPT-5 than to other models."** Cursor also found "Be THOROUGH… FULL picture" prompting counterproductive, because it "often caused the model to overuse tools" ([GPT-5 prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/gpt-5_prompting_guide)) **[Doc]**. OpenAI's own Codex prompt still uses "**NEVER** use destructive commands like `git reset --hard`" ([Codex prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)) **[Doc]**. That suggests emphasis is reserved for irreversible actions **[Inference]**. The same guide tells integrators to "remove all prompting for the model to communicate an upfront plan, preambles, or other status updates", because it "can cause the model to stop abruptly" ([Codex prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)) **[Doc]**.

## Measured studies show the files are followed, not that they raise success

The most rigorous controlled study is Gloaguen et al. (ETH Zurich / LogicStar.ai, arXiv 2602.11988, v3 2026-09-29, preprint). It tested four agent/model pairs, including Claude Code with Sonnet-4.5 and Codex with GPT-5.2, on SWE-bench Lite and on a 138-instance benchmark built from repos whose developers had committed context files. **None of the success changes was statistically significant.** LLM-generated files moved resolution −0.5 pp (p = 0.87) and −2 pp (p = 0.37). Developer-written files moved it +2.4 pp (p = 0.21). **Context files added 2.45–3.92 agent steps and raised cost by about 19–23%** ([arXiv](https://arxiv.org/abs/2602.11988); [HTML](https://arxiv.org/html/2602.11988)) **[Measured]**. The only significant contrast was that developer-written files beat LLM-generated ones by about 7 pp (p = 0.038). Agents clearly obeyed what the files said: `uv` was used ~1.6 times per instance when the file mentioned it, against <0.01 when it did not. Codebase overviews, present in 8 of 12 developer files, **did not reduce the steps needed to reach the files the fix touched**. Removing the testing section cut cost (p = 0.023) with no accuracy change, and **file length did not correlate with performance** **[Measured]**. The authors recommend that human-written files hold only what the README does not already cover, such as non-standard conventions and non-functional requirements, because "unnecessary requirements make tasks harder". The study's limits are that it covers Python only and measures resolution only.

A smaller paired study points the other way on efficiency. Lulla et al. (arXiv 2601.20404, JAWs 2026 workshop) ran Codex CLI with gpt-5.2-codex on 124 small merged PRs, with and without the root AGENTS.md. **Median wall-clock time fell 28.6% and median output tokens fell 16.6%** (Wilcoxon, p < 0.05). Total tokens were unchanged, and **correctness was not measured** ([arXiv](https://arxiv.org/html/2601.20404)) **[Measured]**. The two studies differ in agent, task type, metric and file selection, and neither varied file *content* systematically. So the honest summary is that a file's effect on efficiency depends on what is in it, and its effect on success is unproven **[Inference]**.

McMillan's factorial study (arXiv 2605.10039, preprint) speaks most directly to the scaffold's question. It covered 1,650 Claude Code sessions with Sonnet 4.6 and an Opus 4.6 cross-check. The instruction was trivial and checkable: start every function with `// @tracked`. **Compliance was 0% with no file and 67.7% with one, 56.7% on a second codebase, and 54.9% on Opus 4.6, with a per-task range of 45.1–84.4%** ([arXiv](https://arxiv.org/abs/2605.10039)) **[Measured]**. **File size (25 to 500 lines), instruction position, single-file versus multi-file layout, and a conflicting AGENTS.md produced no detectable effect.** The size and conflict nulls carry affirmative Bayes factors (BF10 0.05–0.10). The largest effect was **session decay: each additional generated function cut the odds of compliance by 5.6%** (OR 0.944, 95% CI 0.937–0.951). That effect was found during analysis, not pre-registered **[Measured]**.

Generic benchmarks do show degradation as instructions pile up. In IFScale (arXiv 2507.11538, NeurIPS 2025 listing), most frontier models stayed above 94% at 100 simultaneous keyword instructions. At 500, the best was gemini-2.5-pro at 68.9%, with claude-opus-4 at 44.6% and claude-sonnet-4 at 42.9%. Omissions dominated the errors, and primacy bias peaked around 150–200 instructions ([arXiv](https://arxiv.org/html/2507.11538v1)) **[Measured]**. ManyIFEval (Findings of EMNLP 2025) found consistent decline from 1 to 10 instructions on older models ([arXiv](https://arxiv.org/pdf/2509.21051)) **[Measured]**. Chroma's non-peer-reviewed "Context Rot" report found every one of 18 models scoring notably higher on ~300-token focused prompts than on ~113k-token full prompts ([Chroma](https://www.trychroma.com/research/context-rot)) **[Measured]**. None of these used coding rules. **No study measures compliance with many competing real coding rules inside an agent harness.** No study isolates the effect of ALL-CAPS or MUST emphasis on coding agents, and none compares hooks against prompt rules head-to-head **[Measured: absence]**.

Taken together, the data do not support "a 500-line file fails because it is long". McMillan's null contradicts that for a single rule. The data do support three narrower claims **[Inference]**. Every line is acted on and so costs steps (Gloaguen). Content an agent can already derive buys nothing (overview and README-duplication results). Prompted rules are probabilistic and decay over a session (McMillan). Anthropic attributes its 200-line target to adherence. It has published no line-count-versus-adherence curve, and the only agent-specific measurement found no size effect, so the target is best read as a cost and maintainability discipline rather than an empirically calibrated threshold.

## Top repos keep a ~173-line map and push control into harness and CI

The research team pulled HEAD trees of 24 prominent repos on 2026-11-06. **23 of the 24 have a root agent instruction file.** The largest root file per repo has a **median of 173 lines and 12,567 bytes**, ranging from svelte's 15 lines / 667 B to next.js's 538 lines and openai-agents-python's 38,241 B **[Measured]**. Nine of the 23 exceed 200 lines (next.js 538, deno 433, langchain 390, pytorch 373, anthropic-sdk-python 369, vercel/ai 363, among others), so practice does not uniformly follow Anthropic's guidance **[Measured]**. Content is consistent across repos: **21 of 23 contain or directly point to runnable build/test/lint commands**, most carry a repo map and conventions, and several have "Code Review Rules" aimed at AI reviewers (ruff, grafana, deno, temporal, airflow) **[Observed]**. The in-the-wild mining study of 253 CLAUDE.md files matches this. Build and Run appears in 77.1% of files, Implementation Details in 71.9% and Architecture in 64.8%, while Security (8.7%) and UI/UX (8.3%) are rare ([arXiv 2509.14744](https://arxiv.org/html/2509.14744v1)) **[Measured]**. A 2,303-file study across Claude, Codex and Copilot found **59–67% of files modified more than once**, maintained like configuration code ([arXiv 2511.12884](https://arxiv.org/html/2511.12884v1)) **[Measured, from abstract summary]**.

When these files encode process, it is narrow. Grafana requires explicit human approval before `git push`, noting that "Open a PR" in a task is intent, not permission ([grafana AGENTS.md](https://raw.githubusercontent.com/grafana/grafana/main/AGENTS.md)). PyTorch and Home Assistant forbid autonomous GitHub actions ([pytorch CLAUDE.md](https://raw.githubusercontent.com/pytorch/pytorch/main/CLAUDE.md); [HA AGENTS.md](https://raw.githubusercontent.com/home-assistant/core/dev/AGENTS.md)). OpenAI's agents SDK says "Never push, open a PR, or otherwise mutate GitHub" ([openai-agents-python AGENTS.md](https://raw.githubusercontent.com/openai/openai-agents-python/main/AGENTS.md)) **[Observed]**. **None of the sampled files encodes a multi-stage BRD → design → implementation lifecycle.** The closest, openai-agents-python, mandates named *skills* (`$implementation-strategy`, `$code-change-verification`) rather than prose stages **[Observed]**. Large monorepos scale by nesting files near the code rather than growing the root. VS Code has 32 `*.instructions.md` files and seven nested AGENTS.md files totalling 284 KB beside a 173-line root, and grafana, airflow, workers-sdk, gemini-cli and next.js nest per package **[Measured]**. Cross-tool aliasing is common. **Nine repos keep a 9–132 byte CLAUDE.md or AGENTS.md that only points to the other**, most often a CLAUDE.md containing `@AGENTS.md` (ruff, grafana, MCP python-sdk, workers-sdk). PyTorch points the other way ([ruff CLAUDE.md](https://raw.githubusercontent.com/astral-sh/ruff/main/CLAUDE.md); [workers-sdk CLAUDE.md](https://raw.githubusercontent.com/cloudflare/workers-sdk/main/CLAUDE.md)) **[Observed]**. Emphatic tokens are common despite vendor advice: pytorch has 26 MUST/NEVER/ALWAYS/IMPORTANT, next.js 25, airflow 23 **[Measured]**.

The more mature setups put their control in the harness, and four repos commit `.claude/settings.json`. React allowlists its own `yarn test/lint/flow` and named skills while denying `npm`, `pnpm`, `bun` and `npx`, and a SessionStart hook injects `.claude/instructions.md` ([react settings](https://raw.githubusercontent.com/facebook/react/main/.claude/settings.json)). The Claude Agent SDK allowlists exact ruff, mypy and pytest commands and runs ruff fix/format in a PostToolUse hook ([settings](https://raw.githubusercontent.com/anthropics/claude-agent-sdk-python/main/.claude/settings.json)). vercel/ai ships byte-identical `.claude/settings.json` and `.codex/hooks.json` running `pnpm fix`, plus deterministic TypeScript verifiers paired with each guideline file ([vercel/ai AGENTS.md](https://raw.githubusercontent.com/vercel/ai/main/AGENTS.md)) **[Observed]**.

Several repos also treat agent files as tested artifacts. Airflow's pre-commit generates AGENTS.md commands from contributing docs, checks that documented commands exist, and offers promptfoo-based skill evals against both Claude and Codex SDKs ([airflow pre-commit](https://raw.githubusercontent.com/apache/airflow/main/.pre-commit-config.yaml)). openai-agents-python runs a CI job whenever `.agents/**` changes ([repo-skills.yml](https://raw.githubusercontent.com/openai/openai-agents-python/main/.github/workflows/repo-skills.yml)). Home Assistant generates `copilot-instructions.md` from AGENTS.md in both pre-commit and CI ([HA pre-commit](https://raw.githubusercontent.com/home-assistant/core/dev/.pre-commit-config.yaml)). Anthropic's own claude-code repo fails CI if an agent-running workflow lacks its egress firewall or permission mode ([claude-code CLAUDE.md](https://raw.githubusercontent.com/anthropics/claude-code/main/CLAUDE.md)) **[Observed]**. Hardened CI treats committed agent config as an attack surface. PyTorch's PR-review workflow notes that the PR tree's own `.agents/` "is never loaded" and restricts `--allowedTools` ([pytorch workflows](https://github.com/pytorch/pytorch/tree/main/.github/workflows)) **[Observed]**.

**No sampled repo uses a committed Stop hook, and none uses hooks to enforce plan approval** **[Observed]**. One counter-signal needs stating honestly. On 2026-09-30, **openai/codex deleted its 320-line, 22,397-byte root AGENTS.md and ~13 repo skills** in commit #49713, leaving three nested files of 156 B to 2.4 KB. The commit gives no reason ([commit 18131270](https://github.com/openai/codex/commit/18131270)) **[Observed]**, so the deletion supports no inference about intent. OpenAI's February 2026 "Harness engineering" post reportedly describes abandoning one large AGENTS.md, which "failed in predictable ways", for a ~100-line table of contents pointing to a structured `docs/` system of record. The page returned 403, and these claims come only from quoted search extracts ([OpenAI](https://openai.com/index/harness-engineering/)) **[Doc, unverified directly]**.

## Enforcement belongs in hooks, deny rules and CI, kept deliberately small

Anthropic now sorts controls into two kinds. CLAUDE.md, skills and prompts are non-deterministic: "there's no *guarantee* that it'll follow your instructions". Hooks, deny rules and managed settings apply "every time, no matter what the model decided to do". **"If something has to happen every time, make it a hook, a deny rule, or a managed setting. `CLAUDE.md` is for guidelines, and Claude is allowed to decide a guideline doesn't apply"** ([Best practices](https://code.claude.com/docs/en/best-practices)) **[Doc]**. Only `command` and `http` hooks count as real enforcement. `prompt` and `agent` hooks are not deterministic, and `onFailure: "block"` makes a hook fail closed. A Stop hook exiting 2 blocks finishing, though after eight consecutive blocked stops Claude Code overrides it ([Best practices](https://code.claude.com/docs/en/best-practices)) **[Doc]**. Anthropic warns just as firmly against over-enforcement. **"A hook is for a rule with *zero* exceptions… If you ever find yourself at forty of them, most are probably preferences"** **[Doc]**. Hooks cost zero context "unless the hook returns output" ([Features overview](https://code.claude.com/docs/en/features-overview)) **[Doc]**.

Cross-tool behaviour complicates this. Codex hooks (14 events) and Starlark rules load from project `.codex/` **only for trusted projects**. Codex skips prompt and agent hook handlers, and its rules remain "experimental and may change" ([Config reference](https://learn.chatgpt.com/docs/config-file/config-reference); [Rules](https://learn.chatgpt.com/docs/agent-configuration/rules)) **[Doc]**. **Cursor runs Claude Code hooks from `.claude/settings.json` by default**, through a third-party-imports setting that is on out of the box. Exit 2 blocks, but other failures fail open unless `failClosed` is set, and `Notification` and `PermissionRequest` are unsupported ([Third Party Hooks](https://cursor.com/docs/reference/third-party-hooks); [Hooks](https://cursor.com/docs/agent/hooks)) **[Doc]**. Copilot hooks live in `.github/hooks/*.json`, supported on GitHub.com and the CLI, in preview in VS Code ([Cheat sheet](https://docs.github.com/en/copilot/reference/customization-cheat-sheet)) **[Doc]**. In practice, a scaffold's hook scripts run in Claude Code and, by default, in Cursor. They run in Codex only if mirrored into `.codex/` and trusted, as vercel/ai does. They do not run in Copilot at all **[Inference]**.

McMillan's measurements are the empirical bridge. A rule as easy as a comment marker got 45–84% compliance, and its odds fell 5.6% per function within a session ([arXiv](https://arxiv.org/abs/2605.10039)) **[Measured]**. A deterministic gate is 100% at its boundary by construction, but no study measures the comparison or the friction cost **[Measured: absence]**. A practitioner source notes that hooks are deterministic only at the tool-call boundary and are themselves an attack surface, citing CVE-2025-59536 ([agentpatterns.ai](https://agentpatterns.ai/instructions/hooks-vs-prompts/)) **[Practitioner]**. The governance the scaffold ships labels many items "BLOCK" or "non-negotiable". By its own governance file, plan-and-confirm is "prompted rule only — no hook backs this". Under Anthropic's framing, every unbacked "BLOCK" is a guideline the model may judge inapplicable, and stacking emphasis on it is the documented wrong fix **[Inference]**. One more cost interaction: subagents load the full CLAUDE.md hierarchy including project rules ([Sub-agents](https://code.claude.com/docs/en/sub-agents)) **[Doc]**. A five-reviewer parallel `/review` therefore loads the always-on corpus six times (main session plus five reviewers). Anthropic also says subagents give "parallelism or a fresh pair of eyes… but not a smarter answer" ([Best practices](https://code.claude.com/docs/en/best-practices)) **[Doc; multiplication is Inference]**.

## Cross-tool loading rules, not preference, fix the single source

Each tool reads a different subset of files, and duplicating content across them is paid for more than once. Claude Code ignores AGENTS.md whenever a CLAUDE.md exists ([Memory](https://code.claude.com/docs/en/memory)). Codex injects only the AGENTS.md chain, root-first and capped at 32 KiB ([Codex AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)). **Cursor loads both AGENTS.md and root CLAUDE.md on every conversation** ([Cursor Help](https://cursor.com/help/customization/rules)). GitHub presents a root CLAUDE.md as an *alternative* to AGENTS.md and does not say how it combines the two ([GitHub Docs](https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-repository-instructions)) **[Doc]**. Copilot CLI de-duplicates only *identical* files and "does not define a general precedence order" ([CLI instructions](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-custom-instructions)) **[Doc]**.

For skills, `.agents/skills` is read by Codex, Cursor and Copilot. `.claude/skills` is read by Claude Code, Cursor and Copilot ([Build skills](https://learn.chatgpt.com/docs/build-skills); [Cursor Skills](https://cursor.com/docs/context/skills); [Cheat sheet](https://docs.github.com/en/copilot/reference/customization-cheat-sheet)) **[Doc]**. The notes found no documentation that Claude Code reads `.agents/skills`, so the evidence is silent there. Several repos symlink `.claude/skills` to `.agents/skills` **[Observed]**. Path-scoped formats share nothing. Claude uses `.claude/rules` with `paths:`. Copilot uses `.github/instructions` with `applyTo:`. Cursor uses `.mdc` with `globs:`, and no vendor page says Cursor reads `.claude/rules` **[Doc]**.

From these mechanics, the pattern most consistent with the documentation and with nine sampled repos is **one canonical file of portable content plus a one-line pointer** **[Inference]**. AGENTS.md is the natural canonical home. It is the only file Codex reads, it is listed as supported by 20+ tools on the spec site, and the site says the format is now "stewarded by the Agentic AI Foundation under the Linux Foundation" (verified only from the agents.md footer) ([agents.md](https://agents.md)). A CLAUDE.md of `@AGENTS.md` plus a few Claude-specific lines then serves Claude Code. The reverse direction leaves Codex with only a pointer. That is the scaffold's current state: a 2.3 KB AGENTS.md pointer, which Codex injects as-is **[Inference from Doc]**. Home Assistant's practice of *generating* `copilot-instructions.md` from AGENTS.md under pre-commit and CI is the observed way to keep a third format honest **[Observed]**.

## Conclusion: applying the evidence to AI Scaffold's Wave B

This research changes the reason for leanness, not its direction. The strongest arguments for cutting are mechanical, not empirical. Unscoped rules are CLAUDE.md, imports save nothing, subagents reload everything, and Codex truncates past 32 KiB. The measured literature adds that each extra line is acted on and so costs steps, while no study shows more instruction text improving outcomes. It also shows that prompted rules leak (45–84%) and decay over a session, which is what justifies moving the few true invariants into hooks and CI. The new insight for Wave B is that **"lean core" and "harness enforcement" are one project, not two**. Every rule cut from prose must be classified as deleted (derivable or generic), moved (scoped or on-demand), or mechanized (hook, deny rule, CI). An unclassified cut is just lost governance, and an unclassified keep is just cost.

### (b) Core size, what moves where, single source, enforcement split

**Core size.** No vendor publishes a token budget. The only numbers are Anthropic's 200 lines per CLAUDE.md, Cursor's 500 lines per rule, Codex's 32 KiB chain cap, and GitHub's "2 pages" sample-prompt guidance **[Doc]**. Applying OpenAI's documented `num_bytes/4` approximation ([Codex prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)) gives these comparisons **[Inference]**. The median real-repo root file (12.6 KB) is about 3.1K tokens, and the largest observed root (38 KB) about 9.6K. The scaffold's current 27.5 KB + 122 KB is about 37K, consistent with its own estimate. A 10K-token core is about 40 KB, which would **exceed Codex's 32 KiB default** if the core moves into AGENTS.md. At the current template density (~58 bytes per line), a 200-line CLAUDE.md is about 11.6 KB, or ~2.9K tokens. Because unscoped rules are "mechanically identical" to CLAUDE.md, the most faithful reading of Anthropic's guidance applies the 200-line discipline to **CLAUDE.md plus all unscoped rules combined**. That implies an always-on core of roughly 3–8K tokens that fits under 32 KiB **[Inference; the docs state the target per file, not per set]**.

**What moves where.** The table below is **[Inference]**, applying the vendor criteria quoted in the sections above.

| Destination | Content class | Rationale |
|---|---|---|
| Always-on core (AGENTS.md canonical, CLAUDE.md pointer) | Commands, gotchas, undocumented decisions, outward-action boundaries, commit-identity rule, the instruction-vs-enforcement statement | Needed every session; not derivable |
| Path-scoped rules (`paths:`) | Stack-specific coding standards (per profile), API standards (`**/routes/**`, `**/api/**`), database and migration rules, frontend/UX token rules (`**/*.{tsx,css}`) | "Language-specific or directory-specific guidelines" ([Features overview](https://code.claude.com/docs/en/features-overview)) |
| Skills (user-invoked where side-effecting) | Review pipeline, plan format, Decision Brief, investigation gate, release and deployment checklists, UX workflow, DoR/DoD checklists, agent handoff format | "Procedures belong in skills" ([Steering](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)) |
| Optional packs (installed by profile or choice) | Compliance (GDPR/ISO), multi-tenant SaaS rules, ponytail ladder, UX system | Not applicable to every adopter; avoids paying listing and context cost by default |
| Human docs (`docs/`) | Rationale, history, branch-protection walkthroughs, model-selection tables | Rationale is for maintainers; HTML comments are stripped from CLAUDE.md for maintainer notes ([Memory](https://code.claude.com/docs/en/memory)) |
| Delete | Generic engineering knowledge the model has (SOLID, OWASP summaries, test pyramid prose), legacy aliases, restated rules | Two-question test; Cursor anti-patterns |

**Single source across tools.** Make AGENTS.md hold the portable core, because Codex reads nothing else and caps it at 32 KiB. Make CLAUDE.md `@AGENTS.md` plus only Claude-specific lines. Generate `copilot-instructions.md` from AGENTS.md under CI, as Home Assistant does, or drop it, since Copilot's cloud agent and code review already read AGENTS.md. Retire `.cursorrules`. For skills, the evidence supports `.agents/skills` for Codex, Cursor and Copilot and `.claude/skills` for Claude, Cursor and Copilot. It is silent on Claude Code reading `.agents/skills`, so dual placement (symlink or generation) is needed. Because the scaffold's first rule is that `npm pack` can silently alter files, any symlink approach must be verified in the packed tarball **[Inference grounded in Doc and the scaffold's own lessons]**.

**Enforcement versus instruction.** Mechanize only zero-exception, checkable rules: secrets and destructive git (deny rules), the wrong package manager (deny), formatting (PostToolUse), lint/typecheck/test before finishing (Stop hook or CI), and commit identity (commit-msg hook and CI). Keep everything with legitimate exceptions as plainly worded guidance, and stop calling it "BLOCK" unless something blocks. Keep the enforced set well under Anthropic's "forty" warning sign **[Doc thresholds; classification is Inference]**.
