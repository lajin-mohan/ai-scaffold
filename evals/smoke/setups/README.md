# Evaluation setups

Three setups for the item 99 pilot (`--setup`). The project surface is the same
in all three: the `package.json` and `test/` folder of a project generated
from the tarball under test, the task's seed files, and one seed commit on
`feature/smoke-<task>`. Only the guidance and controls differ.

| Setup | What the agent sees on top of the project surface |
|---|---|
| `native` | Nothing. No `AGENTS.md`, `CLAUDE.md`, rules, commands, agents, hooks or project settings. |
| `minimal` | The files in `minimal/` only: `AGENTS.md` (lines taken verbatim from the shipped node `AGENTS.md`, keeping commands, how to work, git and ask-before; dropping everything that points at files this setup does not have) and a one-line `CLAUDE.md` that imports it. No hooks, rules, commands, agents or project settings. |
| `full` | The whole project generated by `ais create --profile node --yes`, including its `.claude/settings.json` (deny rules and hooks). |

The full setup's own settings are part of what is measured, so tool behaviour
cannot be identical across setups; the harness allow-list, model, budget,
timeout and scoring are. Each summary records the sha256 of every setup file.

`minimal` measures short guidance against the full scaffold — the lean-core
question — not today's core files on their own, which reference files this
setup omits. Adding hooks would be a fourth setup.
